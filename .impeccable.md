# Impeccable — design context

Design context for Tool-Kit. Loaded by every `/impeccable` skill before it
touches the UI. `src/ui/UI.md` is the design *system*; this file is the design
*brief* the system serves.

## Design Context

### Users

One person, most days: the author, on macOS, with a Finder window open next to
the app. The job is always the same shape — a file exists in the wrong format
and needs to be text a model can read. PDFs of contracts and papers, DOCX from
clients, screenshots, recorded calls.

Two rhythms, and the interface has to serve both without choosing:

- **Drop and forget.** Twenty files in, come back in ten minutes, the results
  are in a folder. The window is a machine that is running; nothing about it
  should demand attention while it works.
- **Drop and read.** One file in, and the point was never the file on disk —
  it was reading and fixing what came back before pasting it somewhere. Datalab
  output is good but not clean: a heading lands as bold body text, a table
  loses a column, page furniture survives as stray lines.

The second rhythm is the one the current UI does not serve. Preview is a
read-only view that replaces the run column, so reading a result means leaving
the thing that produced it.

### Brand Personality

**Engineered, quiet, honest.**

An instrument panel, not a product page. The app states what it is about to do
and what it cost, and never oversells either: the Run button promises the
number of files it will actually bill for, and says "Copy 4 results" when the
run is free. Nothing animates for delight. Nothing is coloured for decoration.

The feeling to produce is *trust under load* — twenty rows finishing out of
order and the window does not move a pixel.

Voice: lowercase-plain, full sentences, no exclamation. "Nothing to do here.
Convert takes PDF, Office and image files." Never "Oops!" and never "Success!".

### Aesthetic Direction

**Extend graphite. The identity is settled and is not the variable.**

Warm charcoal surfaces over real macOS vibrancy; Instrument Serif for display,
JetBrains Mono uppercase-tracked for every label, SF Pro for prose; cobalt for
the control you press; amber/green/red as the only other colours, each carrying
exactly one meaning.

Instrument Serif appears on impeccable's reflex-font reject list. It is kept
deliberately: it is self-hosted, licensed, specimened in the gallery, and it is
the established mark of a shipped app. The reject list exists to stop a *new*
project defaulting into monoculture, which is not the situation here. Treat the
type stack as fixed and spend the design budget on layout instead.

- **Reference:** Yaak's inspector, macOS Shortcuts, the Claude desktop artifact
  panel (for the document-pane mechanics only, not its palette).
- **Anti-reference:** anything that reads as a web app in a window. No cards
  inside cards, no gradient anything, no glass, no coloured icon tiles, no
  toolbar of primary buttons.

Theme: **dark by default**, and this is derived, not fashion — it is a utility
window that sits open beside a Finder window and an editor for hours. `paper`
exists for a future web surface and must keep working.

### Design Principles

1. **Colour is signal, never decoration.** Amber is live, green passed, red
   failed, cobalt the control you press. A fifth meaning needs a new argument,
   not a new hue.
2. **Values light up, they don't appear.** Counts, timers, and dirty marks hold
   their slot as ghost glyphs and brighten. The window never reflows because a
   number arrived.
3. **The window is two applications at two widths.** Compact is a launcher;
   expanded is a workspace. Do not design one layout that stretches — re-rank
   the left column when the document pane opens, because the drop well has
   already done its job and the queue has become navigation.
4. **Reading is a first-class mode, not a preview.** The document surface gets
   prose type, a real measure, and an edit affordance. It is where the second
   rhythm lives, so it may not be a modal, an overlay, or a replaced view.
5. **The interface never lies about cost or state.** A file that will be billed
   says so. A file that was edited and not yet saved says so. Silence means
   nothing happened.
